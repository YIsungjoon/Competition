# FDS: File & Decision System

> 이 문서에서 FDS는 이 프로젝트를 위해 정의한 **File & Decision System**이다. 특정 외부 표준을 그대로 따른다는 뜻이 아니라, 자료와 판단 근거가 유실되지 않도록 만든 로컬 운영 기준이다.

## 1. 목적

최종 아이디어만 남기지 않고 다음 질문에 언제든 답할 수 있게 한다.

- 어떤 자료를 보았는가?
- 어떤 조건에서 얻은 자료인가?
- 무엇이 사실이고 무엇이 해석인가?
- 왜 이 선택을 했는가?
- 어떤 대안을 버렸으며, 다시 검토할 조건은 무엇인가?

## 2. 핵심 규칙

### FDS-01. 원본과 해석을 분리한다

- 사용자 제공 원문과 외부 다운로드 자료는 가능한 한 `raw/`에 보존한다.
- 정제값·요약·선별 목록은 원본과 다른 파일에 둔다.
- 원본을 고쳐 쓰지 않는다. 정정이 필요하면 새 파일을 만들고 이전 파일과의 관계를 기록한다.

### FDS-02. 모든 외부 자료에 출처 ID를 붙인다

- 형식: `SRC-001`, `SRC-002`, ...
- 출처 ID, 접근일, 조회 조건, 파일 위치, 한계를 `source_catalog.jsonl`에 기록한다.
- URL이 없는 사용자 제공 자료도 하나의 출처로 등록한다.

### FDS-03. 숫자에는 조회 조건을 함께 저장한다

예: Google Trends 값에는 지역, 기간, 검색 유형, 비교 검색어 묶음, 접근일을 반드시 붙인다. 조건이 다른 상대지수끼리는 직접 비교하지 않는다.

### FDS-04. 사실·관찰·해석·결정을 구분한다

- `FACT`: 출처가 직접 명시한 내용
- `OBSERVATION`: 도구나 화면에서 직접 읽은 값
- `INTERPRETATION`: 관찰을 바탕으로 한 설명
- `DECISION`: 프로젝트가 채택한 선택
- `ASSUMPTION`: 검증 대기 중인 전제

### FDS-05. 작업에는 목적과 결과를 남긴다

중요 작업마다 `work_log.md`에 다음을 기록한다.

1. 작업 ID와 시각
2. 수행한 작업
3. 수행 이유
4. 입력 또는 출처
5. 결과물
6. 관찰 결과
7. 남은 한계와 다음 작업

### FDS-06. 중요한 선택에는 결정 ID를 붙인다

- 형식: `DEC-001`, `DEC-002`, ...
- 결정, 이유, 근거 출처, 고려한 대안, 위험, 재검토 조건을 `04_decisions/decision_log.md`에 남긴다.
- 아이디어 점수는 결정이 아니라 비교 보조자료다. 최종 선택은 반드시 별도의 결정 기록으로 남긴다.

### FDS-07. 불확실성을 숨기지 않는다

- 데이터가 부분 추출인지 전체 다운로드인지 표시한다.
- 검색어가 중의적이거나 뉴스 사건에 오염됐으면 그대로 기록한다.
- 추정치는 추정 방식과 오차 가능성을 함께 적는다.

## 3. 파일명 규칙

- 영문 소문자와 `_`를 기본으로 사용한다.
- 시점이 중요한 스냅샷: `<주제>_YYYY-MM-DD.<확장자>`
- 원본: `raw/<출처>_<획득일>.<확장자>`
- 같은 날 여러 버전이 필요하면 UTC가 아닌 프로젝트 시간대의 `HHMM`을 덧붙인다.
- 최종본이라는 이유만으로 `final_final_v2` 같은 이름을 쓰지 않는다. 상태는 문서 머리말이나 결정 로그로 관리한다.

## 4. 자료 생명주기

```text
출처 등록
  → 원본 또는 관찰값 저장
  → 정제·선별 규칙 기록
  → 분석 및 해석
  → 후보 아이디어 연결
  → 결정과 근거 기록
  → 최종 산출물 반영
```

## 5. 조사 기록 최소 형식

```markdown
# 조사 제목

- 목적:
- 조사일/시간대:
- 출처 ID:
- 조회 조건:

## 직접 관찰
## 해석
## 의사결정에 미친 영향
## 한계와 반증 가능성
## 다음 확인 항목
```

## 6. 결정 기록 최소 형식

```markdown
## DEC-000 — 결정 제목

- 날짜:
- 상태: 제안 / 채택 / 보류 / 폐기 / 대체됨
- 질문:
- 결정:
- 이유:
- 근거:
- 고려한 대안:
- 위험:
- 재검토 조건:
```

## 7. 현재 적용 범위

이 기준은 아이디어 조사, 사용자 인터뷰, 데이터셋, 기술 실험, 모델 평가, 비용 산정, 배포 검증, 제출 문구에 모두 적용한다. 단순 임시 명령 출력은 보존하지 않아도 되지만, 판단이나 재현에 영향을 준 결과는 반드시 파일로 남긴다.
