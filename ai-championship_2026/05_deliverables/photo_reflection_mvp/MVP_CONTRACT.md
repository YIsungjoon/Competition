# 사진이 묻는 하루 — 출품 MVP 계약

- 아이디어: `IDEA-051`
- 상태: MVP v2 빌드·비공개 저장 버전 완료, 서버 키·실제 사진 검증·프로덕션 배포 대기
- 결정 근거: `DEC-017`, `DEC-018`
- 목표: 사용자가 링크를 열고 3분 안에 `내 사진이 내 기억을 묻고, 내 답이 내 글이 되는 변화`를 이해하게 한다.

## 제품 한 문장

> 하루치 사진을 올리면 AI가 사진 사이의 기억 공백을 세 번 묻고, 사용자가 확인한 말만 사진 근거와 함께 한 편의 일기로 엮는다.

`AI가 사진을 일기로 바꾼다`는 문장은 사용하지 않는다. 자동 캡션·자동 앨범과 구분되지 않기 때문이다.

## 단 하나의 데모 흐름

### 1. 오늘의 사진 선택

- 입력: 한 날짜의 JPG·PNG·WEBP 사진 3~8장
- 화면: 썸네일과 촬영시각, `사진은 질문을 만들기 위해 잠시 사용됩니다` 안내
- 규칙: 위치정보 전송 기본 해제, 원본 영구 저장 없음, 공유 기본 해제

### 2. 하루 타임라인

- 화면: 오전·낮·저녁 장면 묶음
- AI 표시: `사진에서 본 것`과 `아직 모르는 것`을 분리
- 예: `12:41 음식이 놓인 테이블`은 관찰, `누구와 먹었는지`는 미확인

### 3. 기억 인터뷰

- 질문: 정확히 3개, 한 번에 하나씩 제시
- 질문 1: 사진 사이의 사건·장소 변화
- 질문 2: 사진에 담기지 않은 말·소리·이유
- 질문 3: 하루의 의미 또는 남기고 싶은 한 문장
- 사용자는 답하거나 건너뛸 수 있다.
- 사용자의 답에 없는 감정·관계·사건을 AI가 전제하지 않는다.

### 4. 나의 일기와 근거

- 결과: 제목 1개와 4~7문장의 한국어 일기
- 모든 문장에 `PHOTO`, `TIME`, `USER`, `AI_STYLE` 중 하나 이상의 근거가 표시된다.
- 문장을 누르면 연결된 사진과 사용자 답변을 바로 확인한다.
- 사용자는 문장을 수정하거나 전체 결과와 업로드 사본을 즉시 삭제한다.

## AI와 규칙의 경계

| 기능 | 처리 | 이유 |
|---|---|---|
| 촬영시각 추출·정렬 | 규칙 | 같은 입력이면 같은 결과여야 한다. |
| 이미지 축소·위치정보 제거 | 규칙 | 개인정보와 전송비를 줄인다. |
| 사진 속 직접 관찰 | 비전 모델 | 비정형 장면을 읽어야 한다. |
| 사건 후보 묶기 | 시간 규칙 + 비전 모델 | 시간만으로 같은 사건을 판단할 수 없다. |
| 기억 공백 질문 | 생성 모델 | 사진마다 모르는 맥락이 다르다. |
| 답변에 따른 후속 질문 | 생성 모델 | 대화 맥락에 맞게 깊이를 조절해야 한다. |
| 문장별 출처 완전성 검사 | 규칙 | 근거 없는 문장을 실패로 다뤄야 한다. |
| 일기 문체 구성 | 생성 모델 | 사용자의 사실을 자연스러운 서사로 바꾼다. |

## 최소 데이터 계약

```json
{
  "photos": [
    {
      "id": "P01",
      "captured_at": "2026-09-07T09:12:00+09:00",
      "observations": [
        {"text": "창가에 음료 한 잔이 놓여 있다", "confidence": "high"}
      ],
      "unknowns": ["이 음료를 찍은 이유"]
    }
  ],
  "answers": [
    {"id": "U01", "question_id": "Q01", "text": "오랜만에 혼자 쉬는 시간이어서 남겼다"}
  ],
  "sentences": [
    {
      "id": "S01",
      "text": "오랜만에 혼자 쉬는 시간을 사진으로 남겼다.",
      "sources": ["P01", "U01"]
    }
  ]
}
```

출처 배열이 비어 있는 문장은 화면에 표시하지 않고 생성 실패로 처리한다.

## 이번 버전에서 하지 않는 것

- 계정, 친구, 피드, 커뮤니티
- 장기 사진 보관과 전체 갤러리 연동
- 얼굴 인식과 인물 이름 자동 지정
- 감정 점수, 심리 상태 진단, 조언
- 여행기·육아일기·업무일지 등 여러 형식
- 음성 답변, 지도, 알림, 구독 결제
- 여러 모델 제공자를 동시에 지원하는 추상화
- HEIC 직접 업로드와 자동 변환

확장 가능성은 발표 한 장으로만 설명한다. 제품에는 개인 하루 일기 한 종류만 둔다.

## 24시간 통과 기준

| 지표 | 통과 | 실패 시 행동 |
|---|---:|---|
| 관찰·문장 근거 표시 | 100% | 스키마·검사부터 수정 |
| 근거 없는 사실·감정 | 0건 | 생성 결과 폐기 |
| 기억을 새로 떠올리게 한 질문 | 3개 중 1개 이상 | 질문 전략 재설계 |
| 캡션 반복 질문 | 3개 중 1개 이하 | 미확인 정보 입력 강화 |
| 내가 중요하게 생각한 순간이 담겼다 | 5점 중 4점 이상 | 질문·선별 방식 수정 |
| 이 기록을 저장하고 싶다 | 예 | 결과 길이·형식·효용 재검토 |
| 사용자가 말하지 않은 구체 내용 | 0건 | 생성 결과 폐기 |
| 처음부터 결과까지 | 5분 이내 | 입력·질문 수 축소 |

참여자 한 명의 자기평가는 제품 효과를 입증하지 않는다. 첫 구현의 막힘과 안전 실패를 찾는 형성평가로만 사용한다.

## 구현 순서

1. 실제 사진 묶음 하나와 외부 전송 동의 범위를 고정한다.
2. 사진 관찰 JSON만 호출해 사실·추정 경계를 확인한다.
3. 질문 3개를 생성하고 사용자가 직접 답한다.
4. 답변과 사진 ID만으로 근거 있는 문장을 생성한다.
5. 네 화면을 연결하고 마지막에만 공개 배포한다.

첫 단계가 실패하면 로그인·디자인·배포 코드를 만들지 않는다.

## 2026-09-14 구현 상태

- `site/`에 업로드부터 근거 있는 기록 확인까지 전체 수직 흐름을 구현했다.
- 입력 수는 마감·비용·요청 크기 위험을 줄이기 위해 6~10장에서 3~8장으로 변경했다. 결정 근거는 `DEC-021`이다.
- 시간 정렬은 아직 EXIF 촬영시각이 아니라 파일 시간 `File.lastModified` 기준이며 화면에서 촬영시각이라고 부르지 않는다.
- 전송 직전 OpenAI API 전송과 안전 로그 최대 30일 유지 가능성을 고지하고 체크 동의를 받는다.
- 실제 모델 키가 없어 모델 호출은 실행하지 않았다. 샘플 화면·근거 검사·빌드만 통과했으므로 `AI 품질 검증 완료` 또는 `배포 완료`로 표현하지 않는다.
- 상세 관찰과 남은 게이트는 `BUILD_REPORT_2026-09-14.md`에 기록했다.

## PHOTO-P01 1차 결과

- 새 기억을 떠올리게 한 질문: 1/3, 최소 기준 통과
- 반복되거나 불편한 질문: 없음으로 응답, 기준 통과
- 사실과 다른 문장: 참여자가 건너뛰어 미평가
- `내 글 같다`: 1/5. 당시 사전 기준에서는 실패였으나 `SRC-087`의 지표 타당성 이의 후 보조 지표로 강등
- 중요한 순간과 이유 반영: 3/5와 `지금 상태로 나쁘지 않다`는 평가. 수용 가능성은 있으나 기준 4/5 미달
- 수정 판정: 저장 의향과 사용자 미제공 내용 여부를 확인하기 전에는 성공·실패를 확정하지 않는다.

`내 글 같다`는 사용자가 별도로 `내 말투를 보존해 달라`고 선택한 경우에만 문체 유사성 보조 지표로 사용한다. AI에게 정리를 맡긴 결과가 평소 문체와 다르더라도 기억과 의도가 충실하고 저장 가치가 있을 수 있기 때문이다.
