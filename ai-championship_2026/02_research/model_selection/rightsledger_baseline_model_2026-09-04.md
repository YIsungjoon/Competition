# RightsLedger 범용 LLM 기준선 모델 선택

- 목적: 재현 가능한 로컬 범용 LLM 체크리스트 기준선을 정한다.
- 조사일: 2026-09-04, Asia/Seoul
- 출처: `SRC-070`, `SRC-071`, `SRC-072`

## FACT — 공식 모델 정보

- Ollama의 `qwen3:4b` 태그는 약 2.5GB, 256K 컨텍스트의 텍스트 모델이다. Qwen3 소개는 100개 이상의 언어·방언과 다국어 지시 수행 지원을 설명한다. `[SRC-070]`
- Ollama의 `gemma3:4b`는 약 3.3GB, 128K 컨텍스트이며 텍스트와 이미지를 입력할 수 있고 140개 이상의 언어 지원을 설명한다. `[SRC-071]`

## OBSERVATION — 로컬 환경

- 장치: Apple M5, 메모리 24GB.
- 다운로드 후 `ollama show qwen3:4b`에서 모델 ID `359d7dd4bcda`, 4.0B 매개변수, Q4_K_M 양자화, 262,144 컨텍스트, Apache 2.0 라이선스를 확인했다.
- Ollama 공식 문서는 사고 지원 모델의 API 요청에서 `think`를 설정하고, 정상 응답에서는 사고문과 최종 답이 별도 필드로 분리된다고 설명한다. `[SRC-072]`
- 로컬 Ollama 0.24.0과 `qwen3:4b` 조합의 비데이터 점검 2회에서는 `think:false`에도 사고문이 `message.content` 안에 들어가고 마지막에 `</think>`가 붙었다.
- 실험에 필요하지 않은 장치 일련번호와 고유 식별자는 기록하지 않는다.

## DECISION — 선택과 이유

`qwen3:4b`를 범용 체크리스트 기준선으로 사용한다.

이번 기준선은 실제 이미지 해석이 아니라 15개 파일의 경로·추출 텍스트를 한 컨텍스트에서 감사하는 과제다. 따라서 비전 기능보다 한국어 지시 수행, 충분한 컨텍스트, 다운로드·실행 비용이 중요하다. 두 후보 모두 다국어를 지원하지만 Qwen3 4B가 더 작고 텍스트 과제에 충분해 최소 실행 선택으로 채택했다. 이 결정은 Qwen3가 Gemma 3보다 감사 정확도가 높다는 주장이 아니다.

## 고정 실행 조건

- 모델: `qwen3:4b`, 로컬 ID `359d7dd4bcda`
- temperature: `0`
- seed: `20260904`
- num_ctx: `32768`
- thinking: `false`
- 사례당 실행: 1회
- 외부 데이터 전송: 없음
- 출력 정리: 원시 응답을 보존하고 마지막 `</think>` 뒤의 최종 답만 체크리스트 파일로 분리

## 한계

- 두 모델을 한국어 권리 증빙 과제로 직접 벤치마크하지 않았다.
- 4B 양자화 모델은 상용 대형 모델을 대표하지 않는다.
- 현재 5개 사례는 동일 분석자가 만든 합성 데이터이므로 독립 블라인드 검증을 대체하지 않는다.
- 사고문 분리 현상은 이 로컬 모델·런타임 조합의 관찰이며 다른 버전으로 일반화하지 않는다.
