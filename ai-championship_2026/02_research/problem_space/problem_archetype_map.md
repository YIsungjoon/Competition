# 도메인 비종속 문제공간 지도

- 작성일: 2026-09-03
- 상태: 조사 프레임
- 목적: 익숙한 산업이나 기존 솔루션에 고정되지 않고, AI가 만들 수 있는 사용자 가치의 형태에서 후보를 발산한다.
- 관련 결정: `DEC-004`

## 왜 도메인 대신 문제 기능으로 보는가

`건설 AI`, `헬스케어 AI`, `교육 AI`처럼 산업부터 정하면 이미 알고 있는 문제만 반복해서 찾기 쉽다. 반대로 사용자가 겪는 마찰의 구조를 먼저 보면 서로 다른 산업의 해결 방식을 교차 적용할 수 있다.

예를 들어 `흩어진 기록을 사건 타임라인으로 바꾼다`는 구조는 직장 내 괴롭힘, 보험 청구, 반려동물 진료, 고객 분쟁에 모두 적용할 수 있다.

| 코드 | 문제 기능 | 사용자가 겪는 마찰 | AI가 맡을 수 있는 핵심 역할 | 룰·도구가 검증할 부분 |
|---|---|---|---|---|
| PF-01 | 감지 | 사진·음성·시계열에서 이상을 놓침 | 객체·패턴·변화 후보 인식 | 임계값, 센서값, 전문가 확인 |
| PF-02 | 검증 | 진짜·가짜, 안전·위험, 충족·미충족을 판단하기 어려움 | 여러 단서의 맥락 결합 | 공식 DB, 해시, 도메인, 자격 규칙 |
| PF-03 | 번역 | 전문용어·긴 문서·복잡한 화면을 이해하기 어려움 | 사용자 수준에 맞는 설명과 형태 변환 | 숫자·날짜·고유명사 원문 대조 |
| PF-04 | 구조화 | 메모·사진·대화가 흩어져 활용할 수 없음 | 항목 추출, 분류, 타임라인 생성 | 중복·합계·원문 링크 |
| PF-05 | 조정 | 여러 사람의 일정·책임·상태가 어긋남 | 충돌 발견, 인수인계, 다음 질문 생성 | 권한, 마감, 승인 상태 |
| PF-06 | 개인화 | 일반 정보가 내 조건에 맞는지 알기 어려움 | 사용자 맥락과 선택지 매칭 | 필수 조건, 제외 조건, 비용 계산 |
| PF-07 | 시뮬레이션 | 실제 상황 전에 연습하거나 결과를 비교하기 어려움 | 역할극, 상황 생성, 반응 피드백 | 채점표, 시간, 객관 지표 |
| PF-08 | 기억·추적 | 과거 결정과 변화 이유가 사라짐 | 변화 요약, 근거 연결, 회상 지원 | 버전, 작성자, 타임스탬프 |
| PF-09 | 매칭 | 사람·서비스·지원·콘텐츠 중 맞는 대상을 찾기 어려움 | 요구와 공급의 의미 기반 연결 | 자격, 거리, 가격, 가용성 |
| PF-10 | 실행 | 무엇을 해야 하는지 알아도 절차가 길고 누락됨 | 단계 분해, 초안 생성, 상태 추적 | 제출 전 확인, 사용자 승인, 공식 채널 |

## 사용자 상황 10종

문제 기능과 아래 상황을 교차해 아이디어를 만든다.

1. 소비·계약·구매
2. 이동·여행·공간
3. 가족·육아·돌봄
4. 반려동물
5. 창작·콘텐츠·문화
6. 접근성·디지털 소외
7. 환경·에너지·자원
8. 지역사회·공공서비스
9. 일·학습·연구
10. 취미·운동·자기관리

## 아이디어 생성식

```text
구체적 사용자 + 반복되는 실제 입력 + 문제 기능 + 검증 가능한 결과 + 즉시 이어지는 행동
```

예시:

```text
고령 사용자 + 촬영한 병원 안내문 + 번역(PF-03)
+ 날짜·준비물 원문 대조 + 보호자 공유 체크카드
```

## 조사 균형 규칙

- 각 사용자 상황에서 최소 3개 후보를 만든다.
- 동일한 문제 기능이 전체 후보의 25%를 넘지 않게 한다.
- 챗봇·요약·추천이라는 표면 기능만 다른 중복 후보는 하나로 합친다.
- 검색량이 낮아도 피해가 크거나 소수자의 접근성을 개선하면 유지한다.
- 최종 후보를 좁히기 전까지 특정 도메인 경험을 가산점으로 사용하지 않는다.

## 검색 트렌드의 역할

Google Trends는 사용자 상황별로 행동 의도가 있는 표현을 발견하는 데 사용한다. 비교 묶음 간 숫자를 합쳐 도메인 순위를 만들지 않는다. Trends 근거가 없는 후보도 사용자 인터뷰나 공식 통계로 검증할 수 있으므로 폐기하지 않는다.
