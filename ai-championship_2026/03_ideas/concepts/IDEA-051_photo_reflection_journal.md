# IDEA-051 — 사진이 묻는 하루: 대화형 회고 기록

- 기원: 사용자 제안
- 원문: `03_ideas/user_seeds/USER-IDEA-001_photo_reflection_record.md`
- 상태: 2026-09-07 출품 개발 1순위로 전환, MVP 검증 전
- 문제 기능: 구조화(PF-04), 개인화(PF-06), 기억·추적(PF-08)
- 임시 제품 정의: **Photo-grounded Reflective Journal Agent**

## 1. 사용자 원안과 AI 확장의 경계

### 사용자 원안

- 사진 뭉치를 넣는다.
- 사진을 시간별로 나열한다.
- AI가 사진을 보며 질문한다.
- 사용자는 AI와 대화하며 하루를 더 깊게 돌아본다.
- 결과는 일기 또는 다양한 기록이 될 수 있다.

### AI가 추가로 구체화한 부분

- 사진을 사건 단위로 묶는 방식
- 사실·감정·해석을 구분하는 기록 구조
- 문장마다 사진 또는 사용자 답변을 연결하는 근거 구조
- 3분 데모, MVP 범위, 개인정보 안전장치, 평가 방법
- 여행·육아 등 확장 사용례의 구체적 예시

이 구분을 유지하는 이유는 사용자 아이디어의 고유한 핵심을 후속 확장안이 덮어쓰지 않게 하기 위해서다.

## 2. 문제 정의

사람들은 하루 동안 많은 사진을 찍지만 사진은 갤러리에 시간순으로 쌓일 뿐, 그날 무엇을 느꼈고 왜 그 장면을 남겼는지는 기록되지 않는다. 며칠이 지나면 사진 밖의 맥락과 감정은 빠르게 사라진다.

기존의 자동 앨범이나 단순 사진 설명은 `무엇이 보이는가`를 정리할 수 있지만, `나에게 어떤 하루였는가`를 완성할 수 없다. 그 맥락은 사용자의 기억 속에 있으므로 AI가 지어내는 대신 적절한 질문으로 꺼내야 한다.

## 3. 핵심 가치 제안

> 사진을 대신 해석해 일기를 써주는 서비스가 아니라, 사진이 질문이 되어 사용자가 자신의 하루를 다시 발견하게 하는 서비스.

핵심 결과는 예쁜 문장 하나가 아니라 다음 세 가지다.

1. 사진 속 사건의 시간적 흐름 복원
2. 사진 밖에 남아 있는 사용자의 기억과 감정 회수
3. 사진과 답변에 근거한 `내 이야기` 생성

## 4. 핵심 사용자 흐름

```text
사진 여러 장 업로드
  → 촬영시각과 유사 장면으로 임시 타임라인 구성
  → AI가 장면별로 관찰 사실과 모르는 부분을 분리
  → 하루를 복원하는 질문 3~5개 제시
  → 사용자가 답하거나 건너뜀
  → 답변에 따라 한 단계 깊은 후속 질문
  → 사진과 답변에 근거한 기록 초안 생성
  → 사용자가 문장별 근거를 확인·수정
  → 일기 또는 다른 기록 형식으로 저장
```

## 5. AI가 꼭 필요한 부분

| 기능 | AI가 필요한 이유 |
|---|---|
| 장면 이해 | 사진의 사람·장소·행동·분위기 후보를 비정형적으로 읽어야 함 |
| 사건 묶기 | 시간만 가까운 사진이 아니라 같은 사건인지 맥락을 함께 판단해야 함 |
| 질문 생성 | 모든 사진에 같은 질문을 하지 않고 이미 보이는 것과 보이지 않는 기억을 구분해야 함 |
| 대화형 회고 | 사용자의 첫 답변에 따라 더 깊거나 더 가벼운 후속 질문을 선택해야 함 |
| 기록 변환 | 같은 사실을 개인 일기, 여행기, 가족 기록 등 목적에 맞게 재구성해야 함 |

## 6. 규칙으로 처리할 부분

- EXIF 촬영시각 추출과 정렬
- 중복 파일과 거의 같은 연속 사진 탐지
- 사진별 고유 ID와 기록 문장 연결
- 사용자가 답하지 않은 사실을 확정문으로 쓰지 않는 규칙
- 삭제·보관 기간·다운로드·공유 권한
- 위치정보와 얼굴 분석의 명시적 동의

AI와 규칙을 분리하는 이유는 `시간 정렬` 같은 결정론적 작업에 생성 모델을 사용할 필요가 없고, AI의 추정을 사실처럼 기록하는 오류를 줄여야 하기 때문이다.

## 7. 질문 설계

### 나쁜 질문

- `오늘 즐거웠나요?`
- `이 사진에 대해 말해주세요.`
- `사진 속 사람은 친구인가요?`

일반적이거나 AI의 추정을 전제로 하므로 사용자의 기억을 깊게 끌어내기 어렵다.

### 좋은 질문 후보

- `오전 11시 사진과 오후 1시 사진 사이에 장소가 바뀌었습니다. 그 사이에 기억하고 싶은 일이 있었나요?`
- `같은 음식을 여러 각도에서 남겼네요. 맛보다 이 순간을 찍게 한 이유가 있었나요?`
- `이 장면에서 사진에는 보이지 않지만 나중에도 기억하고 싶은 말이나 소리가 있었나요?`
- `오늘 사진 중 하루를 대표하는 한 장을 고른다면 무엇이고, 왜인가요?`
- `이 순간의 나에게 한 문장을 남긴다면 무엇이라고 하고 싶나요?`

질문은 사진에서 직접 관찰한 사실, 불확실한 추정, 사용자가 알려줘야 하는 맥락을 구분해야 한다.

## 8. 기록 결과의 근거 구조

완성 문장은 다음 출처 중 하나 이상에 연결한다.

- `PHOTO`: 사진에서 직접 확인되는 사실
- `METADATA`: 촬영 시각 등 파일 정보
- `USER`: 사용자가 대화에서 직접 말한 기억·감정
- `AI_STYLE`: 사용자가 승인한 표현상의 재구성

예시:

```text
오후 2시, 비가 잠시 멈춘 뒤 한강을 걸었다. [PHOTO-07, METADATA-07, USER-12]
생각보다 마음이 가벼워졌던 순간이었다. [USER-13]
```

근거가 없는 감정이나 인물 관계를 AI가 만들어내지 않는 것이 제품 신뢰의 핵심이다.

## 9. 다양한 기록으로의 확장

핵심 엔진은 `사진 타임라인 + 질문 대화 + 근거 기반 서사`이므로 다음 형태로 확장할 수 있다.

| 기록 형태 | 달라지는 질문 | 결과물 예시 |
|---|---|---|
| 개인 하루 일기 | 감정, 선택, 기억하고 싶은 순간 | 하루 회고문 |
| 여행 기록 | 장소 변화, 예상 밖 사건, 동행자 기억 | 여행기와 지도형 타임라인 |
| 육아 기록 | 성장 변화, 처음 한 행동, 보호자의 느낌 | 성장일기 |
| 가족 기록 | 함께한 사람, 대화, 기념일의 의미 | 가족 앨범 이야기 |
| 반려동물 기록 | 행동 변화, 건강·습관 관찰 | 성장·생활 기록 |
| 프로젝트 기록 | 작업 전후, 결정, 막힌 점, 다음 행동 | 프로젝트 회고 |
| 현장·업무 기록 | 위치, 작업, 이슈, 확인 사항 | 사진 기반 작업일지 |
| 행사 기록 | 준비, 참여, 사람, 인상 깊은 장면 | 행사 아카이브 |
| 학습 기록 | 만든 것, 틀린 것, 이해한 변화 | 학습 포트폴리오 |

## 10. 출원의 범위가 아닌 해커톤 MVP

다양한 기록을 처음부터 모두 구현하면 핵심 경험이 흐려지고 일정 위험이 커진다. 출품용 MVP는 다음으로 제한한다.

- 사용자: 하루를 돌아보고 싶은 일반 사용자 1명
- 입력: 하루치 사진 최대 10~15장
- 타임라인: 촬영시각 기반 사건 묶음 3~5개
- 대화: 핵심 질문 3개와 선택적 후속 질문
- 결과: 개인 일기 1종
- 신뢰 기능: 문장별 사진·답변 근거 확인과 수정
- 확장 데모: 같은 자료를 `여행 기록` 형식으로 한 번 변환

일기를 주 사용례로 고정하는 이유는 감성적 가치와 대화 경험을 가장 짧게 보여줄 수 있기 때문이다. 다양한 기록은 플랫폼 확장 가능성으로 제시한다.

## 11. 3분 데모 시나리오

1. `0:00~0:20` — 하루치 사진 8장을 한 번에 올린다.
2. `0:20~0:40` — 오전·점심·저녁의 사건 묶음이 타임라인으로 나타난다.
3. `0:40~1:30` — AI가 사진 밖의 기억을 묻고 사용자가 짧게 답한다.
4. `1:30~2:10` — 답변에 따라 한 단계 깊은 질문이 나온다.
5. `2:10~2:40` — 내 말이 반영된 하루 일기가 완성된다.
6. `2:40~3:00` — 문장을 눌러 근거 사진과 답변을 확인하고 여행 기록 형식으로 바꾼다.

## 12. 차별화 가설

단순한 `AI 사진 일기`는 기존 사진 설명·자동 앨범·일기 생성 기능과 겹칠 수 있다. 차별화 후보는 다음이다.

1. 생성보다 질문을 먼저 한다.
2. 사용자가 말하지 않은 기억을 지어내지 않는다.
3. 모든 기록 문장을 근거 사진과 사용자 답변에 연결한다.
4. 사진이 적거나 평범해도 사진 밖의 맥락을 회수한다.
5. 사용자가 원하는 회고 깊이와 질문 수를 조절한다.

이 가설은 경쟁 서비스 조사와 실제 사용자 테스트로 검증해야 한다.

### 1차 경쟁 조사 반영

`02_research/competitive/idea_051_competitor_scan_2026-09-03.md`에서 다음 인접 기능을 확인했다.

- Apple Journal: 사진·외출·활동을 묶은 Journaling Suggestions와 성찰 프롬프트
- Google Photos: 사진 검색과 특정 사진에 대한 대화·후속 질문
- Day One: 사진 기반 Journaling Suggestions, AI Daily Chat의 후속 질문과 일기 초안 생성

따라서 `사진 + 질문 + AI 일기`라는 기능 조합 자체는 차별점이 될 수 없다. MVP의 중심을 아래 네 요소로 좁힌다.

1. 글을 먼저 쓰지 않고 하루치 사진 묶음에서 시작한다.
2. 사진 전체를 시간·사건별 시각 타임라인으로 보여준 뒤 질문한다.
3. AI가 사진에 보이는 사실과 사진 밖에 필요한 기억을 구분해 묻는다.
4. 완성된 문장마다 근거 사진과 사용자 답변을 확인할 수 있다.

이 네 요소가 실제 사용자에게 기존 서비스와 다른 가치로 느껴지지 않으면 출품 우선순위를 낮춘다.

## 13. 개인정보와 안전

- 사진 원본, 얼굴, 위치정보는 민감정보로 취급한다.
- 업로드 전 위치정보 사용 여부를 별도로 선택하게 한다.
- 사진 속 인물의 관계·감정·신원을 AI가 단정하지 않는다.
- 공유는 기본 비활성화하고 사용자가 선택한 기록만 내보낸다.
- 보관 기간과 즉시 삭제 기능을 명확히 제공한다.
- 모델 학습에 사진을 재사용하지 않는 정책을 명시한다.
- 가족·아동 사진은 별도의 주의 문구와 최소 보관 원칙을 적용한다.

## 14. 성공 측정

| 지표 | 측정 이유 |
|---|---|
| 사실 수정률 | AI가 사진과 답변을 잘못 연결하는지 확인 |
| 근거 없는 문장 비율 | 환각을 통제하는 핵심 품질 지표 |
| 질문 응답률 | 질문이 부담스럽지 않고 기억을 자극하는지 확인 |
| 회고 깊이 자가평가 | 자동 생성 글보다 더 깊이 돌아보게 했는지 확인 |
| 중요한 순간 반영도 | 사용자가 남기려던 기억과 의미가 결과에 담겼는지 확인 |
| 저장 의향 | 결과가 실제로 보존할 가치가 있는지 확인 |
| 말하지 않은 내용 수 | AI가 사용자의 삶을 대신 지어내지 않았는지 확인 |
| 말투 유사성 선택 평가 | 사용자가 말투 보존을 요청한 경우에만 표현 유사성을 확인 |
| 완료 시간 | 일기를 직접 쓰는 부담을 실제로 줄였는지 확인 |
| 다음날 재방문 의향 | 일회성 데모가 아닌 습관 가능성 확인 |

## 15. 현재 판단

### 강점

- 입력과 결과의 전후 변화가 시각적으로 분명하다.
- 멀티모달 이해, 개인화 질문, 대화형 회고라는 AI 필요성이 있다.
- 누구나 사진을 찍는다는 친숙한 전제 때문에 대중 투표에서 설명하기 쉽다.
- 동일 엔진을 여러 기록으로 확장할 수 있다.

### 위험

- `사진을 글로 바꿔주는 기능`으로만 보이면 흔한 생성형 AI 서비스가 된다.
- 사진 업로드에 대한 개인정보 우려가 크다.
- 질문이 상투적이면 핵심 가치가 사라진다.
- 너무 많은 기록 유형을 한 번에 보여주면 정체성이 흐려진다.
- Day One이 사진 기반 제안과 AI 대화형 일기 생성을 이미 제공하므로 기능 수준의 차별화가 부족할 수 있다.

### 잠정 결론

AI 서비스로서 충분히 성립한다. 다만 핵심 경쟁력은 자동 일기 생성이 아니라 **사진 전체를 이용한 기억 인터뷰, 사용자 기억을 끌어내는 질문의 질, 사진·답변에 대한 근거 추적, 사용자가 자기 기록이라고 느끼는 소유감**에 있다.

### 2026-09-07 전환 기록

작동하는 RightsLedger MVP를 본 프로젝트 제안자가 대회 제출 적합성이 낮다고 판단하고 IDEA-051을 선택했다. 이에 따라 이 후보를 출품 개발 1순위로 올렸다. 이는 최종 우승 가능성이나 사용자 효과가 검증됐다는 뜻이 아니며, `DEC-017`의 질문 품질·근거 무결성·배포 게이트를 통과해야 한다.
