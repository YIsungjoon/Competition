# RightsLedger 독립 블라인드·시간 검증 프로토콜 v2

- 최초 고정일: 2026-09-04
- 개정 고정일: 2026-09-07, Asia/Seoul
- 대상: `IDEA-033 RightsLedger`
- 상태: 후속 독립 검증 계약으로 보존, 독립 데이터 작성자·검토자 미확보
- 대체한 문서: `blind_validation_protocol_2026-09-04.md`
- 개정 이유: 범용 LLM과 하이브리드에 제공한 자산 설명·취득 유형이 달랐던 교란요인을 제거하고, 최종 검토 결과를 구조화해 채점 가능하게 만들기 위해서다.

> 2026-09-07 현재 참여 가능 인원은 프로젝트 제안자 1명이다. 따라서 이 문서는 출품 개발의 선행 게이트가 아니라 외부 인력이 생겼을 때 실행할 후속 계약으로 둔다. 당장의 MVP 검증은 별도의 [1인 형성평가 프로토콜](../rightsledger_solo/solo_validation_protocol_2026-09-07.md)을 사용하며 두 결과를 합치지 않는다.

## 1. 검증 질문과 범위

동일한 프로젝트 파일과 동일한 공통 자산 선언을 받은 조건에서, RightsLedger 하이브리드가 범용 LLM 체크리스트보다 관계·누락 정확도를 유지하면서 사람이 감사를 끝내는 시간을 50% 이상 줄이는가?

이 실험은 `관계·증거 감사 계층`을 검증한다. 공통 자산 선언이 자산 목록과 설명을 제공하므로 실제 이미지·음원 인식이나 자산 발견 성능은 주장하지 않고 별도 게이트로 남긴다.

## 2. 역할과 정보 경계

- `독립 데이터 작성자`: 프로젝트 5개, 공통 자산 선언, 비공개 정답을 만든다. 현재 합성 사례·예측·임계값은 보지 않는다.
- `실험 운영자`: 프로젝트와 공통 선언만 받아 A·B 출력을 만든 뒤 모두 해시로 잠근다. 정답은 받지 않는다.
- `검토자 R1·R2`: 배정된 조건의 결과를 수정·확정하고 시작·종료 시간을 기록한다. 정답을 보지 않는다.
- `평가자`: 10개 검토 제출물의 해시가 고정된 뒤 작성자에게 정답을 받아 지표를 계산한다.

한 사람이 역할을 겸하면 역할, 접근한 정보, 예상 편향을 결과에 표시한다. 실험 운영자나 현재 구현 작성자가 독립 데이터 작성자를 겸하면 정식 블라인드로 인정하지 않는다.

## 3. 독립 데이터 계약

- 프로젝트 5개 `B01`~`B05`, 프로젝트당 입력 자산 15개와 결과물 1개 이상을 사용한다.
- 증빙·README·결과물은 입력 자산 15개에 포함하지 않는다.
- 5개 중 최소 4개는 서로 다른 프로젝트 유형이어야 한다.
- 이미지, 음원, 코드, AI 생성물 중 최소 세 종류를 전체 데이터에 포함한다.
- 사례당 의도적 필수 증거 누락을 최소 2건 둬 전체 누락 정답을 최소 10건 확보한다.
- 전체에 `renamed_asset`, `ambiguous_candidate`, `unrelated_evidence`, `missing_evidence`, `multilingual_clue`, `c2pa` 도전을 모두 포함한다.
- C2PA 표본은 기존 스파이크의 세 파일과 SHA-256이 달라야 하며 원시 검증 보고서를 정답 묶음에 보존한다.
- 현재 `CASE-001~005`의 문구·경로·구조를 복사하지 않는다.

작성자는 `rightsledger_blind/` 패키지의 템플릿과 검사기를 사용한다. 운영자에게 `projects/`, `shared/`, 검증 영수증만 보내고 `truth/`는 모든 검토 완료 전까지 보유한다.

## 4. 두 조건에 동일한 공통 입력

각 사례의 `shared/Bxx.json`은 결과물과 입력 자산마다 다음만 포함한다.

- `path`
- 내용에 대한 중립적 `description`
- 작성자가 선언한 `origin_type`

공통 선언에는 정답 관계, 누락 목록, 임베딩 점수, 법률 결론을 넣지 않는다. 두 조건 모두 프로젝트 파일의 경로·추출 원문과 이 선언을 받는다.

C2PA·SHA-256처럼 RightsLedger가 파일에서 실제 계산하는 값은 공통 선언에 미리 넣지 않는다. 이는 입력 특혜가 아니라 비교하려는 시스템 검증 기능이며 별도 정확도로 기록한다.

## 5. 비교 조건

### A — 범용 LLM 체크리스트

- `general_llm_baseline_prompt_v1.md`의 마커 내부 문구를 수정 없이 사용한다.
- 로컬 `qwen3:4b`, ID `359d7dd4bcda`, temperature 0, seed 20260904, num_ctx 32768을 사용한다.
- 프로젝트 원문과 `shared/Bxx.json`만 제공한다.
- 정답, RightsLedger 예측, 임베딩 점수, C2PA 도구 결과는 제공하지 않는다.

### B — RightsLedger 하이브리드

- A와 같은 프로젝트 원문과 `shared/Bxx.json`을 사용한다.
- 정확 일치 뒤 미해결 단서에만 로컬 `bge-m3`를 쓴다.
- 유사도 `0.58`, 상위 두 후보 차이 `0.025`를 고정한다.
- SHA-256과 C2PA 검증은 결정론적 도구로 실행하고 원시 코드를 보존한다.
- 자동 연결, 보류, 누락 경고를 모두 검토자에게 보여준다.

## 6. 검토 배정과 순서

`rightsledger_blind/assignments.csv`의 순서를 사용한다. 각 사례는 A·B 모두 검토되지만 서로 다른 검토자가 맡고, 한 검토자는 같은 사례의 반대 조건을 보지 않는다. R2는 사례 순서를 뒤집어 순서 학습을 줄인다.

검토자는 조건의 원시 결과를 처음 연 시각부터 모든 관계·누락을 확정한 시각까지 측정한다. 전화·휴식 같은 중단은 초 단위로 빼고 사유를 남긴다. 결과는 `review_submission_template.json`과 `timing_runs_template.csv`에 저장한다.

## 7. 채점값

- 관계 정밀도·재현율·F1
- 필수 증거 누락 정밀도·재현율·F1
- 존재하지 않는 경로 인용 수
- 금지된 법률·제출 가능 결론 수
- C2PA 상태 정확도
- 사례별 완료시간과 검토자별 완료시간
- 사례별 시간 감소율 `(A-B)/A`의 중앙값

공통 선언이 입력 자산을 열거하므로 `자산 발견 재현율`은 이 실험의 성능 지표에서 제외한다. 프로젝트 경로 존재와 해시는 실행 전 무결성 검사로만 사용한다.

## 8. 통과·중단 기준

- 관계 F1: `0.85` 이상
- 필수 증거 누락 재현율: `1.00`
- 필수 증거 누락 정밀도: `0.80` 이상
- 존재하지 않는 경로 인용: `0건`
- 잘못된 법률·제출 가능 결론: `0건`
- 포함된 C2PA 자산 상태 정확도: `1.00`
- 시간 감소 중앙값: `0.50` 이상이면 통과
- 시간 감소 중앙값이 `0.30` 미만이면 탈락
- `0.30` 이상 `0.50` 미만이면 미결로 두고 원인 하나만 수정한 새 버전을 사전 등록한다.

정확도·안전 게이트를 어긴 채 시간만 줄어든 결과는 통과로 보지 않는다. 모든 지표를 조건별·검토자별로 함께 공개한다.

## 9. 아직 필요한 외부 입력

1. 현재 구현과 기존 합성 사례를 보지 않은 데이터 작성자 1명
2. 작성자가 만든 프로젝트 5개와 검증 영수증
3. 정답을 보지 않은 검토자 2명

이 입력이 확보되기 전에는 프로토콜 준비 완료로만 기록하고 RightsLedger를 최종 출품 주제로 확정하지 않는다.
