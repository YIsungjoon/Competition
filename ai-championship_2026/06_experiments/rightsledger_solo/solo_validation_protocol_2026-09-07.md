# RightsLedger 1인 형성평가 프로토콜

- 고정일: 2026-09-07, Asia/Seoul
- 대상: `IDEA-033 RightsLedger` MVP
- 참여자: `P01` 1명 — 프로젝트 제안자이자 제작 의사결정자
- 상태: MVP 종단간 흐름 구현 후 실행
- 목적: 독립적인 효과 입증이 아니라, 한 사람이 실제 흐름을 끝낼 수 있는지와 어디에서 막히는지를 찾는다.

## 1. 이번 평가로 답할 질문

1. 처음 보는 프로젝트 묶음을 열고 감사 결과까지 혼자 도달할 수 있는가?
2. AI가 제안한 자산-증거 관계를 확인·수정할 수 있는가?
3. `증거 누락`, `관계 보류`, `C2PA 무결성`, `서명자 신뢰`, `권리 허락`을 서로 다른 상태로 이해할 수 있는가?
4. 내보낸 기록만으로 어떤 자산에 어떤 추가 확인이 필요한지 다시 설명할 수 있는가?
5. 사용 중 멈춤, 오해, 불필요한 입력은 어디에서 발생하는가?

## 2. 평가하지 않는 것

- 일반 사용자 집단의 만족도나 시장 수요
- 독립 블라인드 정확도
- RightsLedger가 범용 LLM보다 사람 시간을 줄인다는 인과 효과
- 법률상 이용 가능 여부나 제출 가능 여부
- 사진·음원 내용을 자동으로 이해하는 성능

한 명의 자기평가 결과는 위 항목의 근거로 사용하지 않는다. 자동 기술 지표와 1인 사용성 관찰도 서로 합치지 않고 따로 보고한다.

## 3. 준비물

- 종단간 MVP 1개: 프로젝트 불러오기 → 관계 제안 → 확인·수정 → 누락 확인 → 내보내기
- 참여자가 열어보지 않은 합성 테스트 묶음 1개
- 정답표는 세션 종료 전까지 참여자 화면에 표시하지 않는다.
- 화면 녹화 또는 관찰 메모 중 하나. 녹화 시 개인·민감 자료를 사용하지 않는다.
- [세션 기록지](session_record_template.md)

기존 `CASE-001~005`를 재사용하면 이를 명시한다. 참여자가 이미 파일 내용이나 정답을 본 경우 새 합성 묶음을 만들며, 그 이유와 생성 조건을 작업 로그에 남긴다.

## 4. 한 번의 세션

목표 시간은 약 30분이다. 시간은 품질 우위의 증거가 아니라 흐름별 마찰을 찾는 진단값으로만 사용한다.

1. `0~3분`: 한 문장 설명만 읽는다. 기능 시연은 보지 않는다.
2. `3~8분`: 테스트 프로젝트를 불러오고 분석을 시작한다.
3. `8~18분`: 관계 제안을 확인해 승인·보류·수정하고 누락 경고를 검토한다.
4. `18~23분`: C2PA 관련 상태와 권리 증거 상태를 말로 설명한다.
5. `23~27분`: 감사 기록을 내보내고 다음에 보완할 항목을 찾는다.
6. `27~30분`: 가장 혼란스러운 점, 믿기 어려운 점, 유지할 점을 각각 하나씩 기록한다.

진행 중 막히면 60초 동안 스스로 해결을 시도한다. 이후 도움을 받을 수 있지만, 도움을 준 문장과 시각을 기록하고 해당 과제는 `도움 후 완료`로 표시한다.

## 5. 기록 지표

- 과제별 결과: `독립 완료 / 도움 후 완료 / 미완료`
- 과제별 경과시간(초)
- 되돌아가기·잘못 클릭·재입력 횟수
- 잘못 승인한 관계와 놓친 누락 경고 수
- 존재하지 않는 경로를 실제 파일로 오해한 횟수
- C2PA 상태를 권리 허락으로 오해했는지 여부
- 도움을 받은 횟수와 도움 문장
- 세션 후 확신도와 정신적 부담: 각 `1~7`
- 참여자 표현 그대로의 혼란·불신·유지 의견

## 6. MVP 수정 우선순위

- `P0`: 잘못된 권리 결론, 존재하지 않는 경로, 데이터 손실, 세션 완료 불가
- `P1`: 도움 없이는 핵심 과제를 완료하지 못함, C2PA와 권리 상태 혼동
- `P2`: 반복 입력, 의미가 불명확한 용어, 불필요한 이동
- `P3`: 문구·정렬·시각적 다듬기

한 세션 뒤에는 가장 높은 우선순위 원인 하나만 먼저 수정한다. 수정 전 기록은 덮어쓰지 않고 다음 세션은 새 세션 ID로 저장한다.

## 7. 완료 기준과 보고 문구

첫 MVP 세션의 내부 완료 기준은 다음과 같다.

- 다섯 핵심 과제를 모두 최소 `도움 후 완료`
- 잘못된 법률·제출 가능 결론 0건
- 존재하지 않는 경로를 실제 증거로 확정한 사례 0건
- C2PA 상태를 권리 허락으로 해석한 사례 0건
- 발견된 `P0` 문제 0건

통과해도 보고 가능한 문구는 `제작자 1인이 합성 프로젝트로 종단간 흐름을 완료했고, 관찰된 사용성 문제를 기록·수정했다`까지다. `사용자 검증 완료`, `감사시간 50% 감소`, `누구나 쉽게 사용`은 말하지 않는다.

## 8. 독립 프로토콜과의 관계

[독립 블라인드 v2](../rightsledger_24h/blind_validation_protocol_v2_2026-09-07.md)는 폐기하지 않고 후속 검증 계약으로 보존한다. 다만 외부 작성자·검토자를 확보하지 못한 현재 일정에서는 출품 개발의 선행 조건으로 삼지 않는다. 확보되는 즉시 같은 임계값으로 별도 실행하며 1인 기록과 합치지 않는다.
